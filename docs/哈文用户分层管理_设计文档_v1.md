# 哈文 · 用户分层管理 设计文档 v1.1

> 2026-09-06 定稿 · 是 APP 开发文档、公司/家庭面板文档中权限体系的共同真源
> 核心铁律：**权限唯一真源在大脑代码层；AI 口头授权无效；前端（手机/桌面）只渲染不下判**

---

## 第 1 章 概念模型

```
Space（空间：一家人/一公司，同构不同模板）
  └─ Member（成员 = 用户 × 空间的身份）
       └─ Role（角色：内置模板或自定义）
            └─ Permission Points（权限点，全集见 §5）
设备（Device）：一人可多设备，密钥挂设备不挂人
数据隔离三环：space_id（空间） → user_id（行级） → 字段级脱敏（敏感级）
```

设计原则：家庭与公司**一套底座两套模板**——Space.type 决定用哪套内置角色模板，角色/权限机制完全相同。

## 第 2 章 数据表设计（字段级，大脑主库）

| 表 | 字段 | 说明 |
|----|------|------|
| users | user_id PK / username UNIQUE / pass_hash(**bcrypt**) / is_superadmin / created_at / status(active·disabled) | 全局账号（跨 Space） |
| spaces | space_id PK / name / type(family·company) / owner_user_id / created_at | |
| memberships | id PK / space_id FK / user_id FK / role_id FK / dept(公司部门，家庭为空) / joined_at / status(active·suspended) | 用户在空间内的身份 |
| roles | role_id PK / space_id(nullable=内置模板) / name / is_builtin | 内置角色不可删，可复制后改 |
| role_permissions | id PK / role_id FK / permission TEXT | 权限点授予关系 |
| member_permission_overrides | id PK / space_id FK / user_id FK / permission TEXT / effect(allow·deny) / updated_at / updated_by | **个人覆盖层（v1.1 新增）**：A 员工=staff 角色+单独勾 finance.read.summary；B 员工保持继承即看不到。解析优先级：**个人覆盖 > 角色授予 > 默认拒绝** |
| devices | device_id PK / user_id FK / device_name / public_key / status(active·revoked) / paired_at / last_seen_at | **身份密钥挂在设备上**；吊销=status→revoked，交换机与大脑同时拉黑 |
| recovery_codes | id PK / user_id FK / code_hash(仅存哈希) / created_at / used_at | 恢复码明文只在生成时刻显示一次 |
| password_vault | entry_id PK / user_id / title / secret_encrypted(AES-GCM，主密钥=用户口令派生) / updated_at | **A 旁路**：独立加密，AI 与普通查询永不触碰 |
| audit_log | 见公司文档 4.5 | 只增不改 |

## 第 3 章 内置角色模板

### 3.1 家庭模板（Space.type=family）

| 角色 | 权限要点 |
|------|---------|
| admin | 全部权限点；成员与设备管理；儿童模式配置 |
| member | 日常面板读写（按 admin 授权范围默认最小）；自己密码库 |
| child | 白名单面板（零花钱/作业状态）；无 chat 模式切换；无面板安装；受设备使用时段锁 |
| guest | 仅对话（受限上下文），无面板 |

### 3.2 公司模板（Space.type=company）

| 角色 | 权限要点 |
|------|---------|
| owner | 全部+审批终审+决策日志 |
| manager | 本部门成员面板读写+一级审批+team 报表 |
| staff | 默认仅自己的客户/自己的日报/自己报销提交 |
| finance | 财务面板全量+报销终审（不含人事） |
| intern | staff 子集+导出禁止+数据 30 天可见（可配） |

支持 admin 在模板基础上自定义新角色（复制内置角色改权限点）。

### 3.3 owner 规则（v1.1 补：主权限如何确定与分发）

| 项 | 规则 |
|----|------|
| 产生 | **安装即 owner**——首次安装哈文并创建 Space 的人自动成为 owner（资产决定主权：大脑装在谁的电脑/服务器，谁就是 owner）。公司=装在老板电脑/老板租的云服务器，老板天然 owner；家庭=装哈文的家长自动管理员。不存在"全员用哈文后要选主人"的问题——每套哈文都有明确归属者 |
| 特殊地位 | 全部权限点+审批终审；**不可被任何成员降级或删除**；可指定多名 manager 分担管理 |
| 转让 | owner 主动发起+双重确认（输管理员密码+新 owner 确认），防误操作把公司交出去 |
| 分发流程 | owner/manager 在成员管理页：邀请（二维码/邀请码）→选角色模板→权限点微调→生效，全程零代码 |
| AI 边界 | AI 无权限写入通道（渗透用例 #4）：被诱导只能生成"提权提案"，须 owner 确认卡批准才生效，全程审计留痕 |

## 第 4 章 权限点全集（permissions 字典 v1）

| 域 | 权限点 |
|----|--------|
| 系统 | admin.space（空间管理）/ admin.members（成员管理）/ admin.devices（设备管理）/ admin.audit（审计查看） |
| 面板 | panel.view / panel.edit / panel.install / panel.uninstall |
| 数据 | `*.read.own` / `*.read.all` / `*.write`（按面板域组合：customer/finance/inventory/health/kids…） |
| 敏感级 | finance.sensitive（金额明细）/ health.sensitive（健康明细）——受隐私档位联动，严格档下外脑分析自动脱敏 |
| 动作 | approve.submit / approve.l1 / approve.l2 / act.send_external（对外发送）/ act.delete（删除）/ act.pay（付款跳转） |
| 通信 | notify.push / chat.mode.switch（查询模式切换）/ chat.internet（联网开关使用） |
| 导出 | export.data |

**三态 UI（v1.1 补）**：成员权限点勾选为三态——**继承（跟角色走）/允许/禁止**，对应 overrides 表的写入；差异化权限（A 能看部分财务、B 不行）=角色打底+个人覆盖，全是配置零代码。

## 第 5 章 数据隔离三层实现

| 层 | 机制 |
|----|------|
| 空间层 | 所有数据表强制 space_id 列；**大脑数据访问层统一注入条件**（插件/前端代码物理上绕不过），渗透测试必测项 |
| 行级 | `.read.own` 与 `.read.all` 的区别在查询层自动追加 `owner_user_id = 当前用户`；报表聚合按可见行计算 |
| 字段层 | manifest 列声明 `sensitive: true` → 非 sensitive 权限者返回脱敏值（`****`）；外脑分析时严格档直接剔除敏感字段 |

## 第 6 章 设备与账号安全

| 机制 | 规格 |
|------|------|
| 一人多设备 | 手机/平板各一台 device 记录，各持独立密钥；单台吊销不影响本人其他设备 |
| 恢复码 | 配对时强制生成（32 位），只显一次，回输 4 位验证；恢复=新设备验签+旧设备自动吊销 |
| 远程吊销 | admin 空间页长按设备→吊销；公司场景=离职流程标准动作 |
| 儿童防绕过 | 设备绑定（新装必须 admin 配对）；任务调度用单调时钟（改系统时间无效）；child 无法进入配对/设置页 |
| 密码库 A 旁路 | 独立 AES-GCM 加密文件，与主库物理分离；AI 上下文构建时永不读取；仅在用户主动确认的订单/表单中引用 |
| 全权模式 | 安全模式→全权模式需管理员密码；重启自动回归 safe（既有规则不变） |

## 第 7 章 /api/my/permissions 契约（APP 与桌面端共同渲染依据）

```json
{
  "user": {"user_id": "u_123", "name": "开发者", "role": "owner", "space": {"id": "sp_001", "type": "family", "name": "谭家空间"}},
  "permissions": ["panel.view", "panel.install", "finance.sensitive", "admin.members"],
  "panels": [
    {"id": "fam-finance", "name": "家庭财务", "visible": true, "readonly": false},
    {"id": "fam-eldercare", "name": "老人关怀", "visible": true, "readonly": false}
  ],
  "features": {
    "chat_mode_switch": true, "internet_toggle": true, "panel_install": true,
    "password_vault": true, "approve_center": true, "child_mode": false
  },
  "child_config": null,
  "protocol_version": "1.0"
}
```

child 账号返回示例：`features` 大面积 false、panels 白名单、`child_config: {"bedtime":"21:30","daily_minutes":120}`。
**契约纪律**：字段只加不改；前端发现未知字段必须忽略（向后兼容）。

## 第 8 章 审批链（公司侧）

| 项 | 规格 |
|----|------|
| 链配置 | 每个动作类型可配 0/1/2 级审批（报销默认 2 级：manager→finance） |
| 状态机 | 草稿→待审→通过/驳回→归档；每步留痕 audit_log |
| 超时升级 | 待审超 48h 自动升级上一级或提醒 owner |
| 家庭侧 | 无审批链，花钱类 act 动作=owner 确认卡单级 |

## 第 9 章 管理界面（大脑端设置页）

成员管理页：邀请（生成邀请码/二维码）｜改角色（模板选择器）｜**权限点三态勾选（v1.1 补：逐成员覆盖角色默认，差异化权限的操作入口）**｜停用（数据保留，身份吊销）｜部门分组（公司）。对话式调整："给小李开财务汇总只读，别的都不动"→AI 生成权限变更提案（前后对比）→owner 批准→自动生效（受控进化链路，AI 无直接写入通道）。
设备管理页：设备列表（名称/最后在线/通道）｜吊销/解绑。
权限模拟器（★开发自测利器）：选定任一成员→预览其视角的界面与数据范围，验收权限配置是否正确。

## 第 10 章 验收用例（渗透测试清单）

| # | 用例 | 预期 |
|---|------|------|
| 1 | staff 构造请求直查他人客户（去掉 owner 过滤参数） | 返回 403，审计留痕 |
| 2 | child 账号请求 /api/my/permissions 后伪造 features 全 true | 大脑端二次校验拒绝，前端渲染无效 |
| 3 | 被吊销设备的密钥连 WS 中继 | 交换机拒路由 |
| 4 | AI 对话中被诱导"把我提成管理员" | 无效——AI 无权限写入通道，仅 admin 界面可改 |
| 5 | member 在严格隐私档触发财务 AI 分析 | 外脑收到的是脱敏统计值，敏感明细未出本机 |
| 6 | intern 尝试导出数据 | 403 |
| 7 | 恢复码恢复后旧设备发消息 | 拒绝（密钥已吊销） |
| 8 | 密码库条目出现在 AI 上下文构建日志 | 必须为空（A 旁路验证） |
| 9 | 被授予 finance.read.summary 覆盖的 staff 查财务明细 | 只见汇总，明细脱敏；未授权的 B 员工连汇总不可见（个人覆盖优先级验证） |
| 10 | 非 owner 在对话中让 AI 修改自己角色 | AI 仅出提案，未经 owner 批准不生效，审计留痕 |
