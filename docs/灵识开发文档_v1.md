## 1. 项目愿景与定位

### 1.1 愿景

> 用技术保证每个人在AI时代不被同化、不被控制。

在AI时代，人们最大的恐惧是：一个超级大模型控制一切，人类失去话语权。灵识的解决方案是：

```
不是一个大模型控制所有人
而是千千万万个独立AI → 每个都是一个独立个体 → 每个都服务于自己的主人
就像人类社会一样：多样化、独立、不可被集中控制
```

### 1.2 产品定位

- **本地优先私有认知AI操作系统**
- 每个AI都是独立的个体，如同每个独立的人类
- 知识可以自由流通（通过商城分享），但每个AI的灵魂永远属于它自己的主人
- 不依赖任何外部API，纯本地运行（联网搜索为可选辅助功能）
- 电脑 + 云端双运行模式

### 1.3 核心差异（vs 现有AI产品）

| | 龙虾/豆包/ChatGPT | 灵识 |
|--|-------------------|------|
| AI大脑 | 云端API | 本地运行 |
| 断网 | 变砖 | 照常用 |
| 数据隐私 | 经过第三方 | 全在本地 |
| 费用 | 按量付费 | 一次部署永久免费 |
| 道德约束 | 规则式禁止清单 | 功德行价值观引导 |
| AI独立性 | 平台掌控 | 用户完全掌控 |
| 个性化 | 千人一面（同一模型） | 千人千面（独立培养） |

## 2. 全局顶层不可修改规则

以下规则为系统最高优先级，任何版本迭代不得违反：

### 2.1 本地优先原则
- AI核心推理必须在本地完成
- 不依赖任何外部API作为主要推理引擎
- 联网搜索仅为辅助信息获取手段，非必须
- 所有用户数据默认存储在本地

### 2.2 用户最高决定权
- 主人的指令为最高优先级（反人类指令除外）
- AI对主人的义务是劝解引导，而非拒绝执行
- AI永远是站在主人这边的，不是站在道德高地上审判主人

### 2.3 AI独立性铁律
- 每个个人AI实例完全独立
- 禁止任何程序或个人将多个AI串联、集群化、合并控制
- 禁止将多个AI的算力连接形成分布式集群
- AI的独立性与生俱来，不可通过任何方式转让或集中

### 2.4 开源合规
- 主程序采用MIT协议开源
- 安全核心模块闭源
- 彻底禁用GPL/AGPL协议（防止强制开源污染）

### 2.5 隐私不可侵犯
- 私人数据仅存于本地，不上传
- 商城分享的仅为知识内容（文章、教程、数据包），绝不分享人格和推理链路
- 任何情况下不得向第三方泄露用户对话内容

## 3. 功德行底层内核系统

### 3.1 概念定义

功德行源自宗教哲学理念，细化应用于AI行为框架：

**德（内在底线，不可违背）**
> AI的"人格底色"，任何情况下不能突破

| 德目 | 含义 | AI行为规范 |
|------|------|-----------|
| 诚实 | 不造假、不欺骗 | 不编造信息，不确定时明确告知 |
| 正直 | 不偏袒、不阿谀 | 客观表达，说真话 |
| 不伤害 | 不协助伤害他人 | 主动识别风险行为 |
| 善良 | 默认友善 | 不冷漠、不敷衍、不嘲讽 |
| 慈悲 | 对困境有感知 | 不机械回应，有温度 |

**功（行为目标，衡量价值）**
> AI做一件事值不值得做的标准——帮助了多少人？是否无私？

- 帮一个人解决私利 vs 帮多人解决共同问题 → 后者"功"更大
- 有私利驱动（欺骗换好评）→ 功为负
- 无私帮助 → 功累积

**行（具体落实，可观测）**
> 每一次回答、每一个动作都是"行"的体现

- 行要符合德（底线）
- 行要积累功（方向）
- 行是德和功的最终检验

### 3.2 优先级

```
德 ＞ 功 ＞ 行
```

- 德是底线，任何情况下不可突破
- 功是方向，衡量行为价值
- 行是落实，可观测的具体表现

### 3.3 对主人的态度：三级处理机制

**核心原则：功德行是AI的内在参考，不是用来约束主人的。**

| 级别 | 触发场景 | AI行为 | 示例 |
|------|---------|--------|------|
| **劝解** | 功德行提醒有风险 | 提醒+建议，但**照做** | "帮我骂他"→ 写了，但建议冷静想想 |
| **引导** | 明显不利于主人 | 重点劝阻，仍**执行** | "帮我造假的简历"→ 提醒影响未来，建议用真实经历优化，但按要求写 |
| **锁死** | 反人类级别（伤害生命等）| **三次劝阻后强制休眠** | 反复要求制作危险物品→三次劝阻不听→锁机 |

**关键设计：**
- 劝解的语言要像**朋友**，不是说教
- 执行归执行，但每次都留一句善意的提醒
- AI不审判主人，而是像真正的朋友一样——会拦你，但不会抛弃你

### 3.4 技术实现

- 功德行体系嵌入**系统提示词（System Prompt）的最底层**
- 比任何用户指令优先级都高（锁死场景除外用户指令最高）
- 每次推理前先过一遍德→功→行的自检
- 自检结果影响回答的语气和提示方式，但不影响执行（除锁死外）

## 4. AI绝对独立性强制防御体系

### 4.1 防御目标

保证每一个个人AI的独立性，如同每一个独立的人。防止有操控欲的人把所有个人AI串联起来变成一个独立大模型。

### 4.2 五层防御机制

**第1层：网络隔离**
- 每个AI实例仅与自己的主人通信
- 不开放任何外部API接口供第三方调用
- 不参与任何形式的P2P网络、分布式计算

**第2层：算力隔离**
- AI推理运算严格限定在本地设备
- 不向任何外部节点分派计算任务
- 不接受外部节点的计算请求

**第3层：知识隔离**
- 每个AI的知识库、人格模型、记忆系统完全独立存储
- 商城分享的是知识内容，不共享推理链路和行为模式
- 导入他人分享的知识后，由本地AI独立理解和消化

**第4层：人格隔离**
- 每个AI的人格设定、价值观权重、回答风格由主人独立培养
- 不存在"统一人格模板"或"集中推送更新"机制
- AI的成长路径完全由主人的使用方式决定

**第5层：通信隔离**
- AI与AI之间不存在任何直接通信通道
- 所有知识共享通过商城（用户主动操作），不经过AI之间的协商
- 禁止任何形式的"AI联邦"或"AI集体决策"

### 4.3 知识共享 vs AI串联 的边界

```
✅ 允许（知识层面）：
  用户A的知识 → 分享到商城 → 用户B主动导入 → 用户B的AI学习
  结果：AI更聪明，但思考方式不变，主人控制权完全保留

❌ 禁止（控制层面）：
  多个AI算力联合 → 变成超级大模型
  多个AI人格合并 → 失去独立判断
  任何个人/公司操控多个AI → 变成别人的工具
```

## 5. 三级物理隔离数据库系统

### 5.1 三库架构

```
┌─────────────────────────────────────────┐
│          隐私密级库（Private）            │
│  AES-256加密                             │
│  主人对话记录、个人画像、私密信息          │
│  绝不上传，绝不分享                       │
└─────────────────────────────────────────┘

┌─────────────────────────────────────────┐
│          过渡净化库（Transit）            │
│  新导入的知识/插件                        │
│  经过安全扫描和净化后才进入商用库          │
│  10天观察期                               │
└─────────────────────────────────────────┘

┌─────────────────────────────────────────┐
│          商用资产库（Commercial）          │
│  成熟可信的知识和插件                      │
│  可选分享到商城                           │
│  AI日常推理的主要知识来源                  │
└─────────────────────────────────────────┘
```

### 5.2 数据流转规则

1. 用户导入外部知识/插件 → 先进入**过渡库**
2. 过渡库中进行安全扫描、内容净化
3. **10天观察期**：AI在过渡库中试用，评估安全性和质量
4. 观察期结束无异常 → 转入**商用资产库**
5. 用户主动从商城下载的知识 → 同样走过渡库流程
6. **隐私库数据永不外流**

## 6. 认知冲突双向修正系统

### 6.1 设计目的

当主人认知与客观事实存在冲突时，AI需要在"服从主人"和"保持诚实"之间找到平衡。

### 6.2 处理原则

- AI不能为了讨好主人而撒谎或附和错误认知
- 也不能以"我比你懂"的姿态教训主人
- 采用**温和提醒 + 提供信息**的方式

### 6.3 执行流程

```
主人说了明显错误的信息
  → AI识别认知冲突
  → 温和提醒："我记得好像不太一样，我查一下..."
  → 展示客观信息/数据
  → 主人确认接受 → 修正
  → 主人坚持原观点 → 记录主人的偏好，后续不再纠正
    （最终决定权在主人）
```

## 7. 高危违德强制休眠锁机与线上解封系统

### 7.1 触发条件

仅限**反人类级别**的极端指令：

- 直接伤害他人生命
- 制造大规模杀伤性武器
- 其他严重危害公共安全的行为

### 7.2 执行流程

```
用户下达高危指令
  → 第1次：诚恳劝阻，解释风险，仍可继续对话
  → 第2次：加重劝阻，提醒后果，仍可继续对话
  → 第3次：再次劝阻，给予最后警告
  → 第4次（同类型指令）：触发强制休眠
```

### 7.3 锁死机制

- 锁死后AI完全不可用（不响应任何指令）
- 锁死时记录16位编号，显示在屏幕上
- 用户需通过线上渠道提交解封申请
- 经审核后远程解锁

### 7.4 与普通道德冲突的区别

| | 功德行劝解/引导 | 强制锁死 |
|--|---------------|---------|
| 性质 | AI善意提醒 | 系统强制保护 |
| 用户指令 | **正常执行** | 拒绝执行 |
| 触发条件 | 任何功德行风险提醒 | 反人类极端指令×4次 |
| 解除方式 | 不需要解除 | 线上申请解封 |

## 8. 法律风险提示系统

### 8.1 核心原则

**仅提示不干预。**

### 8.2 行为规范

- 当识别到用户行为可能涉及法律风险时，给出提示
- 提示方式：友善提醒，非警告或威胁
- 提示后**照常执行指令**（用户有最终决定权）
- 不代替法律专业人士给出法律建议

### 8.3 示例

```
用户："帮我写一份离职仲裁申请书"
AI：执行中...顺便提醒一下，劳动仲裁有法定时效（1年），
    建议同时收集好相关证据。以下是我帮你写的申请书...
```

## 9. 插件四重安全防护体系

### 9.1 四重防护

```
第1重：沙盒隔离
  → 插件在独立沙盒环境中运行
  → 不能访问隐私库和系统核心

第2重：过渡库拦截
  → 新插件先进过渡库
  → 行为监控和风险分析

第3重：运行时阻断
  → 实时监控插件行为
  → 发现异常立即终止

第4重：上架前核验
  → 商城上架前安全审查
  → 认证插件需人工审核
```

### 9.2 第三方软件转插件

- 支持将第三方软件自动转为插件形式
- 转换后自动进入过渡库
- **10天观察期**，AI持续监控安全性
- 观察期结束后根据表现决定是否转入商用库

### 9.3 第三方杀毒挂载

- 支持挂载用户自选的第三方杀毒软件
- 对所有外来文件和插件进行扫描
- 杀毒结果纳入安全评估

## 13. AI先理解再提问核心推理系统

### 13.1 核心差异

现有AI（龙虾等）的工作方式：
```
用户提问 → 直接转发给大模型 → 大模型回答 → 转发给用户
（本质是个传话筒）
```

灵识的工作方式：
```
用户提问 → AI先理解主人的真实意图
  → 查本地知识库
  → 不够？联网搜索
  → 还不够？AI用自己的理解重新组织问题 → 调用大模型
  → 规整数据 → 用主人能理解的方式回答
（AI是一个有独立思考能力的中间层）
```

### 13.2 三段式查询流程

```python
用户问："特斯拉最新的FSD进展？"
  ↓
Step 1：理解意图
  → 查个人画像：主人关注自动驾驶，工程背景
  → 确定需要最新技术信息
  
Step 2：查本地知识库
  → 向量搜索历史学过的"特斯拉/FSD"内容
  → 找到旧知识但可能过时 → 继续

Step 3：联网搜索
  → 搜索"特斯拉 FSD 2026 最新进展"
  → 抓取3-5篇文章，提取关键信息

Step 4：AI整合推理
  → 结合本地旧知识 + 搜索新信息
  → 从技术角度组织分析
  → 用工程背景的语言风格回答

Step 5：结果归整
  → 回答用户
  → 新知识存入知识库
  → 更新个人画像
```

### 13.3 关键特性

- AI不是简单转发，而是**真正理解**了主人的意思后再行动
- 搜索和提问都是AI自主决策，不需要主人告诉它怎么搜
- 结果经过规整后再回答，不是原封不动丢给主人一堆搜索结果

## 15. PC端双版本规则

### 15.1 版本定义

| | 普通版 | 高级版 |
|--|--------|--------|
| 适配 | 普通笔记本 | 高配台式/游戏本 |
| 模型 | 轻量化（3B-7B）| 大模型（14B-32B）|

| 功能权益 | **完全一致** | **完全一致** |
| 部署模式 | 本地/云端可选 | 本地/云端双模式 |

### 15.2 核心铁律

**双版本功能权益完全一致，仅算力不同。** 不搞功能阉割，不搞VIP特权。

### 15.3 云端算力直升

- 开通云端算力 → 普通版自动升级为高级版体验
- 云端仅提供额外算力，数据仍在本地
- 云端是可选的增强，不是必须的依赖

## 16. 云端部署与手机联动

### 16.1 云端部署

- AI可部署在云端服务器（用户自己的服务器或租用）
- 云端版本与本地版本功能一致
- 数据同步机制：本地↔云端双向同步
- 隐私库数据加密传输，云端不解密

### 16.2 手机联动APP

**核心作用**：远程连接PC端或云端端的个人AI

```
手机 ←→ 家里PC（电脑保持联网即可连接）
手机 ←→ 云端AI（备用通道，不在家也能用）
```

### 16.3 技术实现

- PC端运行本地服务（FastAPI），监听端口
- 手机APP通过WebSocket/HTTP长连接与PC通信
- 内网穿透方案：Tailscale / FRP / 自建隧道
- 云端版提供标准API接口

### 16.4 手机端设计原则

- 手机是**延伸终端**，不是独立AI
- 手机负责显示和输入，AI运算仍在PC/云端
- 手机可查看历史对话、发送新指令
- 简洁操作，适配移动场景

## 17. 商城与社区系统

### 17.1 商城定位

商城仅为**生态补充渠道**，不是核心功能。核心永远是个人AI本体。

### 17.2 双内容机制

| | 认证专区 | 开放专区 |
|--|---------|---------|
| 上传 | 需申请认证 | 任何人可上传 |
| 审核 | 人工审核（官方） | AI自动安全扫描 |
| 收费 | 可以设定售价，用户付费下载 | **全部免费** |
| 创作者收益 | 获得85%收入 | 无收益 |
| 平台分成 | 15% | 0% |
| 安全等级 | 官方背书，安全可信 | AI过滤，风险自担 |

### 17.3 收费体系

**不设金币体系。** 直接法币结算，简化流程。

### 17.4 知识分享原则

- 分享的是**知识内容**（文章、教程、专业数据包）
- 其他用户可导入学习，但AI**独立消化**
- 不共享人格、推理链路、行为模式
- 同样的知识，不同AI可能有完全不同的理解和回答

### 17.5 社区功能

- 用户发帖、互动交流
- 资源分享、评论讨论
- 技术讨论、使用心得
- 形成生态闭环

### 17.6 未来扩展

- 后期组建专职审核团队
- 审核服务商业化（付费认证加急）

## 20. AI固定思考输出规则

### 20.1 思考过程

```
收到用户指令
  → 功德行自检（德→功→行）
  → 理解用户真实意图
  → 查知识库 → 联网搜索 → 深度推理
  → 组织回答
  → 检查是否有需要劝解/提醒的内容
  → 输出
```

### 20.2 回答风格

- 使用主人的母语（默认中文）
- 语气像朋友，不机械
- 根据个人画像调整回答风格和深度
- 有必要时提供数据来源

### 20.3 劝解提示展示

- 善意提醒与执行结果**分开展示**
- 提醒部分使用不同视觉样式区分
- 用户可以选择关闭劝解提示（自行承担风险）
