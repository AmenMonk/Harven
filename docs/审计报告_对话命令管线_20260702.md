## 五、Agent 路由双重执行问题

```
send()
  ├─ Step 0.65: registry.discover() → handoff() → 成功则 return
  │                                          └─ 失败（exception）→ 继续
  │
  └─ _stream_three_stage()
       └─ Step 2.5: registry.discover() → 第二次匹配
                ├─ suggest 型 → 弹通知 + return
                ├─ script 型 → 执行脚本 + return
                └─ 普通 → 覆盖 system_prompt
```

**问题**：
- Step 0.65 的 `handoff()` 如果成功，消息直接 return，**不走后续任何流程**（不存记忆、不提取画像、不学习惯）
- Step 0.65 的 `handoff()` 如果抛异常，消息继续往下走，Step 2.5 又做一次 `discover()` — 可能匹配到同一个 Agent
- Step 2.5 的 Agent 处理逻辑（suggest/script/普通）与 Step 0.65 的 `handoff()` 逻辑**完全不同**

**建议**：统一到一个位置处理 Agent 路由，删除其中一个。
