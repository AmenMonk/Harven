## 第 1 章 产品定位

### 1.1 解决什么问题

家庭管理的三大崩坏点：**忘事**（缴费/保养/疫苗/生日）、**乱账**（钱花哪了没人说得清）、**没人盯**（老人孩子宠物 plants 各有需求但没人专职管）。家庭版用与公司版同构的面板体系解决，但更轻：无审批链、无部门分组、角色只有三档。

### 1.2 与公司版的差异总表

| 维度 | 公司版 | 家庭版 |
|------|--------|--------|
| 角色 | owner/manager/staff/finance/intern + 部门 | admin / member / **child** / guest |
| 审批链 | 1~2 级审批流 | 基本无审批（花钱类动作 admin 确认即可） |
| 敏感数据 | 商业机密级 | 家庭隐私级（健康/财务对 child 完全不可见） |
| 通知强度 | 工作节奏 | 家庭提醒优先级更高（用药/跌倒属 urgent 级） |
| 时间锚点 | 工作日为主 | 全周覆盖（周末家务/兴趣班） |

### 1.3 家庭角色权限基线（详见《哈文用户分层管理·设计文档》）

| 角色 | 财务 | 健康 | 孩子 | 全局设置 |
|------|------|------|------|---------|
| admin | 全量 | 全量 | 全量+设置 | 全量 |
| member | 本人相关+家庭汇总只读 | 本人+被授权对象 | 查看/互动 | 无 |
| child | 不可见（仅自己的零花钱面板） | 仅自己 | 仅自己 | 无 |
| guest | 不可见 | 不可见 | 不可见 | 不可见 |

## 第 2 章 八类面板详细设计

> 格式同公司版：数据表（字段级）→ 页面 → 时间锚点 → AI 分析 → 动作 → 权限。

### 2.1 家庭财务（panel_id: `fam-finance`）

**数据表**

| 表 | 字段 |
|----|------|
| panel_fam_transactions | tx_id PK / type(收入·支出) / category(餐饮·教育·医疗·房贷·车·人情…) / amount / payer_member_id / counterparty / occurred_at / proof_path |
| panel_fam_budgets | budget_id / category / period / limit_amount / warning_ratio |
| panel_fam_bills（周期缴费） | bill_id / name(水电燃气物业) / amount_est / cycle(月·季·年) / next_due / auto_remind_days(默认3) |
| panel_fam_insurances | ins_id / insurant_member_id / company / type / premium / renew_date |

**页面**：流水列表+"记一笔"｜预算仪表盘｜缴费日历｜保单柜
**时间锚点**：缴费提醒（next_due 前 3 天，remind）｜保险续期 90/30 天预警｜每月 1 号家庭支出汇总（report）
**AI 分析**：家庭消费洞察（结构环比+类别占比，schedule·每月）｜预算超支原因分析（event）｜省钱建议（同类目比价/订阅审计，manual）
**动作**：导出年度账本（low）｜缴费跳转（high, needs_approval）
**权限**：admin 全量｜member 家庭汇总只读+自己 payer 记录｜child 不可见

### 2.2 车辆管家（panel_id: `fam-vehicle`）

**数据表**

| 表 | 字段 |
|----|------|
| panel_fam_vehicles | vehicle_id PK / model / plate / buy_date / insurance_due / inspection_due / current_mileage |
| panel_fam_maint_records | rec_id / vehicle_id / type(保养·维修·美容) / mileage / date / cost / shop / items_json |
| panel_fam_fuel_logs | fuel_id / vehicle_id / date / liters / cost / mileage(算油耗) |
| panel_fam_violations | vio_id / vehicle_id / date / type / fine / points / status(待处理·已处理) |

**页面**：车辆卡片（里程/保险/年检三倒计时）｜保养记录时间线｜油耗曲线｜违章列表
**时间锚点**：**保养双触发**（里程间隔 or 时间间隔，先到先提醒，remind）｜年检/保险到期 30 天（remind）｜违章周查（analyze·每周，联网查）｜续保比价提醒（保险到期前 45 天）
**AI 分析**：油耗异常检测（骤增→提示检查胎压/车况，event）｜保养项目比价（4S vs 连锁店历史价，manual）｜年检材料清单生成（act）
**权限**：admin/member 读写｜child 不可见

### 2.3 健康（panel_id: `fam-health`）

**数据表**

| 表 | 字段 |
|----|------|
| panel_fam_health_profiles | profile_id / member_id / blood_type / allergy_json / chronic_json / height_weight_history |
| panel_fam_meds（用药计划） | med_id / member_id / name / dosage / times_json(每日时刻) / start_date / end_date / active |
| panel_fam_vaccines | vac_id / member_id / name / done_date / next_due |
| panel_fam_visits（就诊） | visit_id / member_id / date / hospital / dept / diagnosis / prescription_path / cost |

**页面**：成员健康卡（过敏史置顶）｜用药计划表｜疫苗/体检时间线｜就诊档案
**时间锚点**：**每日用药提醒**（times_json 逐时刻，urgent 级通知，30 分钟未确认→升级通知 admin，remind）｜体检年检（年度，remind）｜疫苗补种（remind）
**AI 分析**：用药依从统计（给家属看，schedule·每周）｜就诊记录整理归纳（manual）｜就医建议提示（症状描述→建议科室，manual，附"非诊断"免责）
**摄像头**：药盒拍照识别核对（防止拿错药）
**权限**：admin 全量｜member 本人+被授权查看对象｜child 不可见
**红线**：健康数据属最敏感级，严格隐私档下不出本机；AI 输出必须带"仅供参考非医疗建议"

### 2.4 孩子教育（panel_id: `fam-kids`）

**数据表**

| 表 | 字段 |
|----|------|
| panel_fam_homework | hw_id / child_id / subject / desc / due_date / status(未做·完成·已检查) / photo_path |
| panel_fam_exams | exam_id / child_id / name / date / subjects_json / score_json |
| panel_fam_classes（兴趣班） | cls_id / child_id / name / schedule_json(周几几点的循环锚点) / place / prepaid_hours |
| panel_fam_allowance | allow_id / child_id / date / amount / direction(发·支出·存) / balance |

**页面**：孩子卡片（今日作业/下周课程）｜作业拍照入口📷｜考试记录｜零花钱账本（child 可见自己）
**时间锚点**：**放学接送提醒**（child 课表锚点，前 30 分钟，urgent）｜作业催办（due 前一晚 19:00）｜零花钱发放（每周固定日，act 自动记账）｜考试倒计时（remind）
**AI 分析**：**作业拍照批改**（拍照→视觉识别→批改建议→家长确认，manual）｜学习趋势（成绩+作业完成率曲线，schedule·每月）｜兴趣班性价比复盘（出勤率/进度 vs 花费，schedule·每季）
**权限**：admin 全量｜member 查看｜child 仅自己：零花钱+作业状态（成绩对 child 可选显示）

**学习闭环与边界（v1.1 补）**：摸底建档（年级+教材版本+薄弱项初测）→ 每日拍照上传作业/试卷 → AI 批改 → 错题按知识点归档 → 错题变式出新题+趣味讲解（闯关/积分，激励方式按孩子画像动态调）。三条边界：①数学/英语客观题可全自动批改，**语文作文/主观题只给评语与建议分，不判最终分**（判错伤孩子）②出题对齐教材版本（人教/苏教等，摸底时问清，否则孩子觉得"学这个干嘛"）③时间管理=作业番茄钟+休息护眼提醒，**玩的时间也是排程的一部分**——排的是"完成目标前提下玩得理直气壮"，孩子才不烦。

### 2.5 冰箱·饮食（panel_id: `fam-fridge`）

**数据表**

| 表 | 字段 |
|----|------|
| panel_fam_food | food_id / name / qty / unit / expiry_date / added_date / source(手动·拍照识别) / photo_path |
| panel_fam_menus | menu_id / date / meals_json(早中晚) / dishes_json |
| panel_fam_shopping | item_id / name / qty / status(待购·已购) / linked_food_id |

**页面**：冰箱列表（按保质期分色：临期红/一周黄/正常绿）｜今日/本周菜单｜购物清单（勾选模式）
**时间锚点**：**保质期预警**（到期前 2 天，remind）｜每周菜单生成（周日晚 AI 生成下周菜单+联动购物清单，act·需确认）｜周日采购提醒
**AI 分析**：菜谱推荐（按现有食材+家人口味画像，manual）｜食材浪费分析（月度，schedule）｜购物清单联动（菜单→缺什么自动加清单，act）
**摄像头**：**冰箱开门拍照→视觉识别食材→自动入库/更新**（本面板核心体验，免手动录入）
**外卖入库（v1.1 补）**：外卖平台不开放订单接口（美团/饿了么不提供）——主路径=**订单页截图→本地视觉识别→自动入库+记账**，零硬件即可用；常用菜品识别一次后记住映射（"黄焖鸡米饭"→需米饭），越用越准；入口做成长按图标秒传截图（3 秒内完成，否则坚持不了）；定期冰箱拍照盘点校准清单。微信/支付宝账单导出仅作记账金额补充（拿不到菜品明细）。
**权限**：全家读写，child 只读

### 2.6 家务·生活（panel_id: `fam-chores`）

**数据表**：panel_fam_chores（chore_id / name / assignee_member_id / cycle_json(轮换规则) / next_due / done_log）｜panel_fam_packages（pkg_id / carrier / track_no / status / arrived_at）

**时间锚点**：值日轮换提醒（每周日生成下周值日表，act）｜快递到货通知（event）
**AI 分析**：家务分担公平度统计（谁做多了，schedule·每月，评事不评人版家庭应用）
**权限**：全家

### 2.7 家庭事务（panel_id: `fam-events`）

**数据表**：panel_fam_events（event_id / type(生日·纪念日·聚会) / person_id / date(支持农历) / repeat_yearly / gift_ideas_json）｜panel_fam_albums（album_id / month / auto_generated / photos_json / note）

**时间锚点**：生日/纪念日提前 7 天备礼提醒（含礼物点子，remind）｜每月家庭相册自动整理（act：按照片时间线归类生成月度相册）｜年度家庭大事记（act·每年 12 月）

### 2.8 老人关怀（panel_id: `fam-eldercare`）★社会价值最大的面板

**数据表**

| 表 | 字段 |
|----|------|
| panel_fam_elders | elder_id / name / relation / address / phone / health_ref(关联健康面板) |
| panel_fam_checkins | checkin_id / elder_id / date / method(电话·短信·APP·上门) / responded(bool) / responded_at / note |

**时间锚点**：**每日问候**（固定时刻如 10:00，remind→老人在 APP 回复或接电话即确认）｜**未响应升级**（30 分钟未响应→通知所有 admin/member，urgent；2 小时未响应→建议上门/联系邻居，actionable 通知）｜定期复诊提醒
**AI 分析**：活动量异常（响应率骤降/话变少→提示关注，schedule·每周，评事不评人）｜用药联动（健康面板用药计划自动纳入问候内容）
**摄像头**：**跌倒检测**（老人房 IP 摄像头本地视觉分析，仅异常事件通知，画面不出本机；需老人知情同意）
**权限**：admin/member 全量｜child 不可见
**四层看护体系（v1.1 补，哈文定位=看护协调员，不是医生）**：

| 层 | 规格 |
|----|------|
| 日常守护（V1 即可） | 每日问候+未响应升级+用药打卡——不依赖任何硬件的保底方案 |
| 健康档案 | 血压/血糖记录（老人语音报数或拍照血糖仪）、用药清单、症状日志；**就诊时一键生成"给医生看的 summary"一页纸**（慢性病真正痛点=见了医生说不清，这才是对就诊的最大帮助） |
| 连接医生（合规路径） | ①社区卫生服务中心**家庭医生签约**（国家政策，免费/低价，哈文管预约与随访记录）②互联网医院在线问诊（京东健康/平安好医生等，哈文帮挂号/整理病历/提醒问诊/归档医嘱）③**哈文永不问诊开药**——诊断和处方永远是医生 |
| 紧急链路 | 未响应/跌倒异常→通知子女→紧急联系人→提示拨打 120；**AI 不自动呼救**（先弹"确认呼救"卡片给子女，超时无响应才升级）——误报的代价是急救资源与邻里信任双输；跌倒自动报警场景优先推荐老人智能手环（比摄像头可靠，见 7.3） |

**商业化潜力**：独立包装为"安心守护"套装——独居老人家庭刚需，社区/物业合作渠道

**能力两档边界（v1.1 补）**：**拍照识别类**（食材识别/作业批改/药盒核对）V1 即可实现——本地视觉模型现成，主要是串流程；**实时监控类**（跌倒检测/宠物异常）列 **V1.5**——跌倒等检测需专用人体姿态小模型（不能靠通用视觉模型聊天式判断），误报率需实测定标；V1 期间实时类场景一律用"定时问候+未响应升级"兜底。

## 第 4 章 生活助手插件（panel_id: `fam-assist`）

对话式完成：订机票/火车票/酒店、订餐（家庭聚餐/宴请推荐）、医院挂号、各类缴费、快递寄收。流程一律：AI 给方案卡（含价格对比）→ 用户点确认 → 跳转支付/下单 → 回填行程到家庭事务日历。身份证/证件号存密码库（A 旁路），AI 仅在用户确认的订单中引用，日志脱敏。

| 时点 | 动作 |
|------|------|

## 第 7 章 智能家居与低成本硬件（v1.1 新增）

### 7.1 架构：哈文当大脑，Home Assistant 当手

```text
传感器/设备（米家、涂鸦等现成硬件）
    ↓ 数据流
Home Assistant（开源中枢，纯局域网可跑，社区已适配 2000+ 设备）← 哈文不自研设备适配层
    ↓ 状态查询 + 执行指令
哈文（AI 大脑层）：读传感器 → 判断 → 建议规则 → 用户批准 → 规则存 HA 永久自动执行
```

- AI 不 24 小时盯着设备跑（费电费算力）：**AI 的价值是帮用户写自动化规则**（"近一周 15:00 家里最热，建议 14:45 预开空调"→批准→HA 永久执行）+ 异常播报（"客厅湿度连续 3 天超 75%，可能漏水"）
- 动作档位沿用《公司文档 4.10》AI 四档授权：开关灯/调温可 L3 白名单；**门锁/燃气类动作永远 L4 观察员（只报告，绝不自动操作）**
- 为什么接 HA 而非哈文直连米家：自适配几百种设备是无底洞，HA 已把脏活干完且纯局域网可跑，符合本地优先

### 7.2 绿植照料（不造硬件）

土壤湿度传感器（米家/涂鸦生态，30-80 元/个）→ 数据进哈文 → 干了提醒"阳台绿萝该浇水了"；授权后联动现成自动浇水器（100-200 元）低湿自动滴灌（L3 白名单，额度=水箱容量，天然安全）；手机定期拍叶子 → AI 识别黄叶/虫害 → 提示。

### 7.3 硬件总原则：软件是哈文的，硬件买大厂现成件

| 需求 | 现成方案 | 参考成本 |
|------|---------|---------|
