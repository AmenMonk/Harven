# Harven AI 模式架构重构 — 技术设计文档

> 版本：v1.1 | 日期：2026-06-26（更新协作规则） | 作者：开发者 & Harven AI

## 一、背景与目标

本次重构源于对 Harven AI 三种查询模式的深度讨论，核心目标：

1. **修复侧边栏按钮无响应**（知识库、数据保险箱等点击没反应）
2. **修复外脑连接失败时前端无提示**
3. **重新设计三种模式的架构**，对齐最终设计决策（12项已确认）
4. **梳理与现有代码的冲突**，制定修改计划

## 二、侧边栏按钮无响应 — 根因分析

### 2.1 症状

左侧按钮（📚 知识库、🔐 数据保险箱、🎯 专项培养、📋 任务管理、🔔 监控中心、🤝 多Agent）点击无任何反应。

### 2.2 完整点击链路追踪

```
┌─ [HTML] sidebar-footer 按钮 ────────────────────────────────────────┐
│  <button class="btn-sidebar" data-modal="dataVaultModal" id="btnDataVault"> │
└─────────────────────────────────────────────────────────────────────┘
                                    ↓ click
┌─ [L192-229] 内联事件委托（sidebarFooter.addEventListener('click')）─┐
│  ① e.target.closest('.btn-sidebar') → 找到按钮                       │
│  ② modalId = btn.getAttribute('data-modal') → "dataVaultModal"      │
│  ③ typeof window.openModal === 'function' → TRUE (head占位函数)      │
│  ④ window.openModal(modalId) → 推入 _openModalQueue                 │
│  ⑤ 6秒超时 → 检查 _openModalReady → 未就绪则弹 alert              │
└─────────────────────────────────────────────────────────────────────┘
                                    ↓
┌─ [L914] app-settings.js 加载 ───────────────────────────────────────┐
│  ① window.openModal = openModal (真正实现)                           │
│  ② window._openModalReady = true                                    │
│  ③ 补执行队列: _openModalQueue.forEach(id => openModal(id))         │
└─────────────────────────────────────────────────────────────────────┘
                                    ↓
┌─ [L7] app-settings.js → openModal(id) ──────────────────────────────┐
│  ① document.getElementById(id).classList.add('active')              │
│     ❌ 没有 style.display='flex' ！                                 │
│  ② 依赖 CSS: .modal-overlay.active { display: flex; }               │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.3 根因确认

**核心问题：`openModal` 只有 `classList.add('active')`，不设内联样式，纯靠 CSS。**

对比 head 中的 `_forceOpenModal`（L70-98）：

```javascript
// ✅ _forceOpenModal — 双保险（class + inline）
el.classList.add('active');
el.style.display = 'flex';        // ← 内联样式，优先级最高
el.style.visibility = 'visible';
el.style.opacity = '1';
el.style.zIndex = 2001;
el.style.pointerEvents = 'auto';

// ❌ openModal (app-settings.js L7) — 单保险
document.getElementById(id).classList.add('active');
// 仅依赖 CSS: .modal-overlay.active { display: flex; }
```

**如果 CSS `.modal-overlay.active` 规则因任何原因失效**（选择器特异性冲突、CSS 加载失败、被其他规则覆盖），modal 就不会显示。

### 2.4 次要发现

| # | 问题 | 位置 | 严重度 |
|---|------|------|--------|
| 1 | 内联事件委托优先调用 `window.openModal`（占位函数），从不走 fallback 分支（L202-207），fallback 代码永远是死代码 | L202-207 | 中 |
| 2 | `openModal` 队列超时 6 秒后才弹 alert，用户体验差 | L63-65 | 低 |
| 3 | body 内联脚本（L976-1025）重新定义了 `openDataVaultModal` 等，但侧边栏委托从不调用它们 | L976-1025 | 低 |
| 4 | `dataVaultModal` 定义在 `modal-数据保险箱.html`（L1092 include），而不是 index.html 主文件中，依赖 Jinja2 include 正确执行 | L1092 | 低 |

### 2.5 修复方案

**方案：侧边栏内联委托直接使用 `_forceOpenModal`（跳过队列）**

```javascript
// 修改 L196-229 内联事件委托
// 将 L201-208 改为：
if (modalId) {
    // 直接使用 _forceOpenModal（class + 内联样式双保险）
    window._forceOpenModal(modalId);
    return;
}
```

**理由：**
- `_forceOpenModal` 已定义在 head（L70），比 sidebar 事件委托早，永远可用
- 使用双保险（class + inline style），不依赖 CSS 加载状态
- 跳过队列机制，即时响应
- 无需修改 app-settings.js

**同时修复 app-settings.js `openModal`**：

```javascript
// L7-8，加一行内联样式：
function openModal(id) {
    var el = document.getElementById(id);
    if (!el) return;
    el.classList.add('active');
    el.style.display = 'flex';  // ← 新增：与 _forceOpenModal 对齐
    // ... 原有懒加载逻辑不变
}
```

## 三、外脑连接失败 — 前端提示缺失

### 3.1 现状

`_route_model_for_query`（engine.py L556-615）在外部模型不可用时会自动回退 Ollama，**但回退是静默的**：

```python
# engine.py L612
logger.debug(f"[Engine] {query_mode}模式：无可用外部模型（未启用或无API key），回退Ollama")
return False, "本地 Ollama", "ollama"
```

用户侧看不到任何提示，不知道外脑已经断开。

### 3.2 修复方案

**后端**（engine.py）：回退时 yield 通知标记

```python
# 在 _route_model_for_query 回退 Ollama 的位置（L612 前后）
# 在 _stream_three_stage 中 L739 之后添加：

if not use_external and self._query_mode in ("direct", "auto"):
    yield ("notification", {
        "type": "foreign_model_fallback",
        "message": "⚠️ 外脑不可用，已切换为本地 Ollama",
        "reason": "no_api_key" | "not_enabled" | "network_error"
    })
```

**前端**（app-send.js / app-core.js）：处理 `notification` 类型

```javascript
// 在 stream 处理中新增：
case 'notification':
    if (data.type === 'foreign_model_fallback') {
        showToast(data.message, 'warning');
    }
    break;
```

## 四、新模式架构定义

### 4.1 三种模式（最终确认版）

| 模式 | 原名 | 图标 | 核心组成 | 回答者 |
|------|------|------|----------|--------|
| **自动模式** | auto | ⚡ | Harven框架 + Ollama + 知识库 + Skills + 外脑（可选） | Ollama（整合所有信息） |
| **本地模式** | kb_only → 🏠 | 🏠 | Harven框架 + Ollama + 知识库 + Skills | Ollama |
| **外脑模式** | direct → 🤖 | 🤖 | Harven框架 + 外部模型 + Skills | 外部模型 |

### 4.2 协作模式（自动模式的子模式）

| 项目 | 定义 |
|------|------|
| 触发 | 用户在设置中选择「协作外脑」并开启 |
| 角色 | Ollama = 执行者，外部模型 = 外脑（参谋） |
| 限制 | **只能1个外部模型**，禁止2个外部模型同时工作 |
| 外脑选择 | 设置→模型管理→协作外脑下拉菜单 |
| 存储 | `config.yaml` → `collab_foreign_model: "doubao"` |
| Skills注入 | 参考 OpenClaw：system prompt 注入工具描述，外部模型返回 JSON 格式工具调用，Harven 本地执行 |
| 隐私保护 | 三档：严格（不传用户数据）/平衡（传去敏数据）/全量（传全部） |
| 外脑断开 | 提示「⚠️ 外脑不可用」+ 自动回落 Ollama |

### 4.3 联网搜索

**决定：取消。** Playwright 保留为独立功能。

### 4.4 模式流转图

```
用户选择模式
    │
    ├─ ⚡ 自动模式 ──→ 查询知识库 + Ollama 判断
    │       │              │
    │       │         ┌────┴────┐
    │       │     需要外脑?  不需要
    │       │        │         │
    │       │   协作外脑可用?  Ollama直接回答
    │       │     │      │
    │       │    是     否 → ⚠️提示→Ollama回答
    │       │     │
    │       │  外脑分析→返回结果→Ollama整合回答
    │
    ├─ 🏠 本地模式 ──→ 知识库 + Ollama + Skills → 回答
    │                    （绝不外传数据）
    │
    └─ 🤖 外脑模式 ──→ 外部模型 + Skills → 回答
                         （外脑断开则提示+回落）
```

## 七、注意事项

1. **禁止联网搜索后**：`_classify_query` 中的 `need_web` 判断保留，但始终返回 `False`
2. **协作模式是最复杂的部分**：需要 OpenClaw-style Skills 注入，建议先实现 P1/P2，P3 单独规划
3. **Flask `debug=False` 模板缓存**：修改 HTML template 后必须重启 Flask，之前已多次遇到缓存问题
4. **config.yaml 污染**：保存时必须使用 `yaml.dump(dict(config), ...)`，不能直接 dump 对象
5. **不要删除 `_web_search_enabled` 相关代码**：标记废弃即可，Playwright 独立功能可能还需要
