| 指标 | 数值 |

### 1.2 技术栈

```
后端：Flask 3.0 + SSE 流式
AI 引擎：Ollama（本地）+ 多云端 API（DeepSeek/Kimi/GPT/Claude 等）
向量检索：FAISS-CPU（384维 embedding）
数据库：SQLite（WAL 模式，3个物理隔离库）
桌面 GUI：PyQt6（可选）
语音：faster-whisper（本地模型 138MB）
浏览器：Playwright（自动化）
前端：原生 HTML/CSS/JS（无框架），Service Worker（PWA）
```

### 1.3 一句话定位

> **纯本地优先的私人专属 AI 操作系统**，核心理念是"不是一个大模型控制所有人，而是千千万万个独立 AI 各为其主"。

### 2.2 架构评价

| 维度 | 评分 | 说明 |
|------|:--:|------|
| 分层清晰度 | ⭐⭐⭐⭐ | core/api/ui/data 四层分明 |
| 模块解耦度 | ⭐⭐⭐ | engine 与 web_app 耦合较多；云端路径独立 |
| 可扩展性 | ⭐⭐⭐⭐ | 插件/技能/设备驱动均支持扩展 |

| 配置管理 | ⭐⭐⭐⭐ | config.yaml 统一管理 |

**主要架构问题**：

1. **🔴 云端/本地双路径分裂**：`web_app.py` 中 `active_provider != 'ollama'` 走独立代码路径，完全跳过 `ConversationEngine`，意味着**安全审查、知识库检索、记忆注入、用户画像在云端模型路径全部失效**。

2. **🟡 桌面版/Web 版代码重复**：`main.py`（PyQt6）和 `web_app.py`（Flask）各自独立初始化数据库、模型管理器等，维护成本高。

## 三、核心模块逐项分析

### 3.1 engine.py — 对话引擎（35.9KB）

**功能**：
- 三段式查询：插件匹配 → 意图分类 → 知识库/联网搜索/直接回答
- 集成功德行道德审查（lockdown 检查）
- 集成用户画像注入
- 集成 Memory Dreaming
- 支持流式/非流式输出

**评价**：⭐⭐⭐⭐

**强项**：
- 完整的三段式查询流程
- 流式生成器设计合理

**弱项**：
- `_classify_query()` 基于简单关键词匹配，未使用 LLM 意图分类
- 云端模型路径完全绕过此引擎（见 web_app.py 第195行）

---

### 3.2 knowledge_base.py — 知识库（51.2KB，最大模块）

**功能**：
- FAISS 向量检索（384维 embedding）
- 支持 40+ 文件格式（PDF/MD/TXT/代码等）
- 自动分块（chunking）策略
- 启动时自动扫描新文件并导入（哈希追踪去重）
- PDF 导入（PyPDF2/pdfplumber）

**评价**：⭐⭐⭐⭐

**强项**：
- 支持格式多，覆盖实际需求
- 自动导入 + 哈希去重逻辑完善
- FAISS 检索性能好

**弱项**：
- embedding 模型选择策略不透明（默认 384 维，应该是 all-MiniLM-L6-v2）
- PDF 导入曾出现编码问题
- 知识库元数据文件已膨胀到 1.6MB

---

### 3.3 memory.py + active_memory.py + memory_dreaming.py — 记忆三部曲

#### memory.py（17.8KB）— 五重防失忆

**功能**：L0 原始对话 → L1 任务记忆 → L2 长期记忆，基于规则提取

**评价**：⭐⭐⭐

**强项**：结构完整，分层清晰

**弱项**：L1 记忆提取基于简单正则匹配（`"我喜欢"`, `"我叫"`），未使用 AI 语义提取

#### active_memory.py（10.6KB）— 主动记忆检索

**功能**：对话时自动拉取相关历史记忆，注入上下文

**评价**：⭐⭐⭐⭐

**强项**：关键词→分类映射合理，自动注入逻辑清晰

**弱项**：检索也基于关键词，未使用 FAISS 语义检索

#### memory_dreaming.py（18.2KB）— 记忆巩固

**功能**：三阶段梦境（Light→Deep→REM），参考 OpenClaw 设计

**评价**：⭐⭐⭐⭐

**强项**：设计完整，三阶段逻辑清晰，已集成到 web_app 启动流程

**弱项**：Deep Dream 和 REM Dream 依赖 LLM 调用做语义蒸馏，但当前 LLM 函数注入在 web_app.py 中（第108行），桌面版未注入

---

### 3.4 morality.py — 功德行道德内核（20.9KB）

**功能**：
- LLM 意图复核（v2.0）
- 窗口制计数器（按天重置，同类累计）
- 分级锁死（30分钟 → 2小时 → 人工解封）
- 宽松原则：先劝解再执行，反人类才锁死

**评价**：⭐⭐⭐⭐⭐

**强项**：
- 设计理念优秀——"AI 永远站在主人这边"
- v2.0 的 LLM 意图复核远优于关键词匹配
- 分级锁死机制合理
- 善意提醒格式温和不越界

**弱项**：
- LLM 意图复核只在本机 Ollama 可用时生效
- 云端模型路径完全跳过功德行审查

---

### 3.5 device_binding.py — 设备绑定防克隆（12.6KB）

**功能**：
- 五维硬件指纹：MAC + CPU 序列号 + 主板 UUID + 磁盘序列号 + 机器 GUID
- 多因素校验（至少 2/3 匹配）
- 首绑+续绑机制
- 启动时自动校验

**评价**：⭐⭐⭐⭐

**强项**：采集维度全面，校验逻辑完善

**弱项**：
- Windows 专有实现（`getmac`, `wmic`），跨平台需重写
- 防克隆仅在一台机器上有效，虚拟机克隆场景未测试

---

### 3.6 isolated_db.py — 三库物理隔离（6.0KB）

**功能**：隐私库/过渡库/商用库三个独立 SQLite 数据库

**评价**：⭐⭐⭐⭐

**强项**：
- 架构设计正确——物理隔离优于逻辑隔离
- 每库独立 SQLite 文件，安全边界清晰

**弱项**：
- 当前三库目录 `data/isolated_dbs/` 为空，尚未在生产路径中使用
- 过渡库和商用库的表结构比较简单，缺少审计日志

---

### 3.7 multi_model_manager.py — 多模型管理（20.9KB）

## 四、安全体系分析

### 4.1 六层洋葱模型

```
┌─────────────────────────────────────────┐
│ 第一层：入口安全    ✅ 设备绑定+绑定校验   │
├─────────────────────────────────────────┤
│ 第二层：输入过滤    ⚠️ 功德行（仅本地路径）│
├─────────────────────────────────────────┤
│ 第三层：执行隔离    ✅ Docker+子进程+黑名单│
├─────────────────────────────────────────┤
│ 第四层：通信控制    ❌ 无SSRF防护          │
│                     ❌ 无速率限制          │
├─────────────────────────────────────────┤
│ 第五层：系统守护    ❌ 无 Ollama 守护进程   │
│                     ❌ 无内存淘汰策略       │
├─────────────────────────────────────────┤
│ 第六层：数据隔离    ✅ 三库物理隔离        │
└─────────────────────────────────────────┘
```

### 4.2 安全盲区

| 级别 | 问题 | 影响 |
|:--:|------|------|
| 🔴 P0 | 云端路径跳过功德行审查 | 用户切换到 DeepSeek 等时，全部安全机制失效 |
| 🔴 P0 | 无 SSRF 防护 | 联网搜索可被利用访问内网资源 |
| 🟡 P1 | 无请求速率限制 | 可能被暴力对话消耗资源 |
| 🟡 P1 | 外部文件下载无病毒扫描 | GitHub 下载器等直接写入本地 |
| 🟢 P2 | Ollama 无守护进程 | Ollama 崩溃后需手动重启 |
| 🟢 P2 | 无内存淘汰策略 | 长时间运行可能导致 OOM |
