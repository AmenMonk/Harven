# 哈文 · 智能公司面板平台 开发文档 v1.3

> 2026-09-06 定稿 · 配套《哈文开放架构设计 v1》契约文档第 7 章 · 面向开发者与产品验收
> 定位：以时间为基准的自动提醒与运行的多功能集合体，可随意安装组合，承接一切、运行一切
> 一句话：**闹钟是入口，参谋是价值，帮手是护城河**

---

## 第 1 章 产品定位与设计哲学

### 1.1 解决什么问题

企业主三大管理死因：**记不住**（事项/节点遗忘）、**算不清**（钱货账目模糊）、**盯不住**（执行进度失控）。本平台用"面板插件 + 时间调度 + AI 四层智能"逐一补齐，让不擅长管理的人也能把公司管起来。

### 1.2 设计哲学（全平台铁律）

| # | 铁律 | 说明 |
|---|------|------|
| 1 | 四层智能 | 层1 记录（数据表）→ 层2 提醒（时间锚点）→ 层3 分析（AI 洞察建议）→ 层4 执行（AI 动手，高危需批准） |
| 2 | 结构统一，内容无限 | 任何面板 = 数据表 + 时间锚点 + 动作 + 权限 + AI 分析声明。结构一旦定死，新面板只是"填内容" |
| 3 | 评事不评人 | AI 分析输出客观行为数据，不做对"人"的主观定性（态度/忠诚度等），规避员工监控法律风险 |
| 4 | 完整单件分批上架 | 每个面板上架必须全链路闭环（数据+提醒+分析+导出），禁止任何"敬请期待"式半成品 |
| 5 | 记忆真源本地化 | 外脑是用完即走的计算工人；"懂你"的画像/习惯/数据沉淀全部在哈文本地，换外脑不丢记忆 |
| 6 | 权限在代码不在嘴上 | 一切权限校验在大脑代码层执行，AI 口头授权无效；手机/前端只渲染不下判 |
| 7 | 高危动作人工确认 | 对外发送、删除、资金相关动作必须老板/授权人批准后执行 |

### 1.3 理论支撑（对外宣传可用）

贝尔宾团队角色理论：AI 补位**信息密集型角色**（情报员✅✅/智多星✅/监督评价者✅/完成者✅），人守住**人际密集型角色**（协调者/凝聚者/形象大使）。小公司最缺的"军师+秘书+质检"恰是 AI 强项——"5 个人的公司具备 15 个人的参谋体系"。

## 第 2 章 总体架构

### 2.1 分层结构

```
┌─────────────────────────────────────────────┐
│  作战室（老板总览页）← 目标引擎（旗舰插件）      │
├─────────────────────────────────────────────┤
│  面板插件层：18 类分类目录（开放 category）      │
│   客户/财务/库存/汇报/电商/采购/营销广宣/        │
│   客服售后/人事/行政/法务/质量安全/IT资产/       │
│   参谋/规划/决策日志/公告…                      │
├─────────────────────────────────────────────┤
│  横切能力层：审批中心 | 通知中心 | 审计日志       │
├─────────────────────────────────────────────┤
│  调度内核（harness，独立进程）                  │
│   时间调度器 | 任务队列 | 插件生命周期管理        │
├─────────────────────────────────────────────┤
│  哈文大脑底座：SQLite 主库 | RBAC | Skill 沙箱  │
│   FC 工具 | 通知推送 | 受控进化 | 画像记忆       │
└─────────────────────────────────────────────┘
```

### 2.2 调度内核（harness）规格

| 项 | 规格 |
|----|------|
| 进程形态 | 独立进程（与 Flask 主进程分离），IPC 或轻量 HTTP 通信；崩溃自动重启且不影响主服务 |
| 规模预估 | 第一版 ≤900 行 Python；只做三件事：时间调度、任务队列、插件生命周期 |
| 调度粒度 | 支持 cron 表达式 + 间隔 + 日历锚点（具体日期/工作日/每月N号/相对天数） |
| 错过任务处理 | 大脑重启后扫描过期任务：提醒类→标记"错过"进待处理列表（UI 显式列出，用户选补发/放弃）；分析类→静默补跑一次 |
| 单调时钟兜底 | 关键提醒（合同到期/证照年检）记录目标时间戳，防系统时间被改导致漏触发 |
| 多 Space | 调度任务必带 space_id；切换空间互不可见 |

### 2.3 插件生命周期

```
上传(Hub或本地) → 安装（manifest 校验+权限清单展示+用户逐项批准）
→ 激活（自动建数据表+注册调度任务）→ 运行（四层智能循环）
→ 暂停/卸载（默认保留数据可导出，彻底删除需二次确认）
→ 升级（数据表自动迁移，破坏性变更需用户确认）
```

## 第 3 章 插件规范（manifest 契约）

### 3.1 目录结构（复用哈文 Skill 三件套范式）

```
data/panels/<panel_id>/
├── manifest.json      # 契约声明（下表全字段）
├── index.html         # 面板 UI（iframe 沙盒内运行）
├── panel.css
├── panel.js           # 通过 HarvenPanel API 与大脑通信
└── scripts/main.py    # 可选：复杂逻辑/自定义分析脚本（AST 沙箱）
```

### 3.2 manifest.json 全字段定义

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | ✅ | 全局唯一，`[a-z0-9-]`，如 `crm-followup` |
| `name` | string | ✅ | 显示名（中文） |
| `version` | string | ✅ | semver 格式 |
| `type` | enum | ✅ | `panel` / `agent` / `skill` / `tool` |
| `category` | string | ✅ | **开放填写**（非枚举）：如 `客户·销售`。分类目录自动归组，新类合法 |
| `author` | string | ✅ | 作者 |
| `license` | string | ✅ | SPDX 标识：MIT/Apache-2.0/proprietary |
| `origin` | enum | ✅ | `uploaded_original` / `imported` / `fork` —— 版权边界校验依据 |
| `icon` | string | ✅ | emoji 或图标路径 |
| `description` | string | ✅ | 一句话说明 |
| `min_harven_version` | string | ✅ | 最低兼容哈文版本 |
| `permissions[]` | string[] | ✅ | 权限点申请（见 4.4），安装时用户逐项批准 |
| `db.tables[]` | object[] | ✅ | 数据表声明：`{name, columns:[{name,type,nullable,comment}]}`，安装时自动建表，表名强制加 `panel_<id>_` 前缀 |
| `schedule[]` | object[] | ✅ | 时间锚点：`{task_type, cron_or_anchor, payload}`；`task_type ∈ remind / analyze / act / report`。**默认值为模板预设，安装即实例化为用户配置（fork 语义），任意字段可覆盖修改，模板升级不回写** |
| `ai.analysis_items[]` | object[] | ⭕ | `{item, trigger(schedule/event/manual), input_scope, output_to}` —— AI 分析声明 |
| `ai.model_pref` | enum | ⭕ | `local_first`（默认）/ `external_only` / `local_only` |
| `ui.entry` | string | panel✅ | 入口 HTML |
| `ui.size` | enum | ⭕ | `half` / `full` / `card`（作战室装配用） |
| `actions[]` | object[] | ⭕ | 对外动作：`{name, risk_level(low/high), needs_approval(bool)}` |
| `sandbox` | enum | ✅ | `skill`（AST 沙箱）/ `iframe`（纯 UI）/ `none` |
| `space_scoped` | bool | ✅ | 固定 true：数据归属 Space |

### 3.3 Hub 上架审核规则（硬性）

1. 全链路闭环：数据 + 提醒 + 分析 + 导出，缺一不收
2. `origin != uploaded_original` 时禁改名称/描述/作者（只可下架）
3. license 必填；imported 件必须保留原作者署名
4. `actions[]` 中 `needs_approval=true` 的动作必须在 UI 有确认弹窗
5. 禁止任何形式刷量/水军类功能声明（违法，直接拒）

## 第 4 章 通用机制（所有面板共用，开发一次全平台受益）

### 4.1 数据库规范

| 规则 | 内容 |
|------|------|
| 存储位置 | 哈文主库（SQLite）内，**不建独立库文件** |
| 表命名 | `panel_<panel_id>_<表名>`，安装时按 manifest.db.tables 自动创建 |
| 必备列 | 每表强制：`id`(主键)、`space_id`(隔离)、`created_at`、`updated_at`、`deleted_at`(软删除) |
| 隔离 | 所有查询强制带 `space_id` 条件（大脑数据层统一注入，插件代码绕不过） |
| 卸载 | 默认保留数据 + 提供导出（Excel/CSV）；彻底删除需二次确认 |
| 备份 | 随主库统一备份；建议大脑端"定时备份"内置插件 |

### 4.2 时间调度（四类任务）

| task_type | 含义 | 错过处理 | 示例 |
|-----------|------|---------|------|
| `remind` | 提醒通知 | 标记"错过"，待处理列表显式补发 | 3天未跟进、合同到期 |
| `analyze` | AI 分析（层3） | 静默补跑一次 | 每日简报、异常检测 |
| `act` | 执行动作（层4） | 不自动补跑，进待确认列表 | 自动发周报、发催款函 |
| `report` | 生成报告 | 静默补跑 | 周报汇总、月度对账 |

**手机端日历双写**：`remind` 任务创建时同步写一份到已配对手机的本地日历/闹钟（防大脑死机漏提醒），触发后自动标记失效。

### 4.3 AI 分析三层触发

| 触发 | 机制 | 呈现 |
|------|------|------|
| 定时自动 | `ai.analysis_items[].trigger=schedule`，按时间锚点后台跑 | 面板"AI 简报"卡片 + 通知 |
| 事件自动 | `trigger=event`，数据越阈值即时触发（异常支出/低库存/进度滞后） | 弹通知 + 面板红点（只推"需决策"的，普通波动只留红点，防骚扰） |
| 手动点击 | 面板"问哈文"按钮，对话式深挖可追问 | 对话气泡 |

算力分级：浅层（阈值/统计）→ 本地模型；深层（趋势/方案）→ 外脑，受隐私档位约束（严格档敏感数据不出本机）。自动分析可按面板在设置中关闭。

### 4.4 权限点字典（permissions[] 取值）

```
panel.view / panel.edit          面板查看/编辑
finance.read / finance.write     财务读/写（含金额敏感级）
customer.read.own / customer.read.all   仅自己客户 / 全部客户
inventory.read / inventory.write
hr.read / hr.write               人事数据（敏感级）
approve.submit / approve.l1 / approve.l2   提交审批 / 一级审批 / 二级审批
notify.push                      发通知
report.generate                  生成报告
export.data                      导出数据
admin.space                      空间管理（仅管理员）
```

RBAC 角色模型：`owner(老板) / manager(部门负责人) / staff(员工) / finance(财务) / intern(受限)`，公司模板可扩展部门分组层。**角色定义与校验全在大脑**，前端仅渲染。

### 4.5 横切能力（平台层，不属于任何面板类）

| 能力 | 规格 |
|------|------|
| **审批中心** | 统一审批流：提交→逐级审批（可配 1~2 级）→留痕。所有面板的审批（报销/请假/采购/用章/合同）共用，`approve.*` 权限点控制。状态机：草稿→待审→通过/驳回→归档 |
| **通知中心** | 全平台唯一推送出口。消息结构：`{space_id, source_panel, level(info/warn/urgent), need_action(bool), payload}`。插件禁止自建推送通道。按空间/来源过滤、已读管理 |
| **审计日志** | 记录"谁在何时对哪块数据做了什么"（查看/修改/导出/审批）。只增不改；既是安全留痕，也是"评事不评人"的客观数据源 |

### 4.6 面板修改机制（三层，"活的模板"实现）

| 层 | 改什么 | 怎么改 |
|----|--------|--------|
| ① 配置层 | 提醒规则参数、字段显隐/必填、AI 分析开关与阈值、报告风格 | 面板设置页直接改，即时生效 |
| ② 结构层 | 自定义字段/类目（如客户表加"竞品名"列） | 面板设置"自定义字段"，数据存扩展列（JSON），不改代码 |
| ③ 对话层 | 上述覆盖不了的改动 | 跟哈文说 → AI 出提案 → 用户批准 → 自动改表改页（受控进化链路） |

**fork 语义（铁律）**：安装模板 = 实例化一份归用户所有。模板作者升级时询问用户是否更新，**绝不覆盖用户已修改的配置和数据**。

### 4.7 新手引导（四套，全大白话，零术语）

| 机制 | 说明 |
|------|------|
| 首开向导 | 面板第一次打开：3 步（这面板干嘛 → 先做一件事 → 去哪看结果） |
| 上下文感知"问哈文" | 面板右下角常驻入口；AI 读 manifest 字段注释 + 当前页面状态，回答带具体操作指引（"点右上角『记一笔』"），因此每个面板无需单独编写帮助文档 |
| 主动教学 | 检测某用户 7 天未用某功能 → 推一条小贴士（每天最多 1 条，防骚扰） |
| 引导数据来源 | manifest 的 columns[].comment 即 AI 教学问答的依据，要求面板作者认真填写 |

### 4.8 摄像头接入（公司/家庭两模板通用）

| 项 | 规格 |
|----|------|
| 接入源 | ①手机/平板摄像头（拍照/即拍即传）②IP 摄像头 RTSP 拉流→定时抽帧（默认每 30 秒一帧，可配） |
| 分析引擎 | 本地视觉模型（minicpm-v 等，4070 12GB 可跑），**禁止原始画面出本机** |
| 事件触发 | 识别结果达阈值→生成 event 任务→走通知中心；仅异常画面缩略图随通知展示（可关闭） |
| 公司场景 | 门店客流统计（进店人数/高峰时段→经营简报）、仓库/车间违规检测（安全帽/消防通道占用→即时预警）、设备仪表读数（拍照识别→自动录入，免人工抄表）、收发货拍照留痕（归档库存流水） |
| 红线 | 拍到访客/员工需场所告知；不做人脸身份识别（除非员工知情同意的考勤场景）；监控画面不入大模型上下文 |

### 4.9 AI 制作中心（层4 标准动作，全平台共用）

制作能力作为 `act` 任务的标准动作集，各面板按需调用，不单独立类；同时开放给 Hub 第三方面板（生态抓手）。

| 动作 | 底层 | 替代的外包 |
|------|------|----------|
| 文案生成（产品文案/脚本/朋友圈，3版供选） | 外脑文本 | 文案写手 |
| 海报/配图生成（AI 生图+模板排版） | 生图模型 | 设计外包 |
| 视频粗剪（脚本+配音+字幕） | moviepy FC | 视频剪辑 |
| 合同初稿+风险条款提示 | 法务面板调用 | 法务助理 |
| 审计自查报告/凭证核对 | 财务面板调用 | 审计助理 |
| 标书/报价书/PPT 结构+填充 | pptx/docx FC | 文员 |
| 简历初筛/JD/员工手册/培训材料 | 人事面板调用 | 人事外包 |
| 翻译 | 外脑 | 翻译 |

**替代边界（写进对外宣传协议）**：AI 替代"初稿、整理、提醒、信息"四类劳动；签字、盖章、付款确认、终审永远是老板。

### 4.10 AI 四档授权（★AI 运用宪法，全平台通用，家庭版同引）

AI 的正确姿势不是"只建议"或"全自动"二选一，而是**按动作风险分档：小事自动做、中事做好等批、大事只参谋**。

| 档 | AI 干什么 | 人批准？ | 准入条件 | 例子 |
|----|----------|---------|---------|------|
| **L1 只参谋** | 分析+建议，不动手 | — | 默认档 | 流失预警、超支分析 |
| **L2 草拟+确认** | 干到 99%（草稿/表单/订单），人看一眼确认 | ✅ 点一次 | **对外发声与花钱的最高档** | 催款函、报销单、订机票 |
| **L3 白名单自动** | 直接执行，做完通知 | ❌ | 仅限**低风险+可撤销+有额度**动作 | 日报汇总、采购单草稿、自动分类记账 |
| **L4 观察员** | 永远只报告不动手 | 🚫 绝对禁区 | 不可逆/高危动作 | 删数据、解约；智能家居的门锁/燃气 |

**判定规则一句话：出错能不能挽回 + 损失有没有上限。**

**信任阶梯（权限是挣来的）**：默认 L1 → 某类动作连续做对 N 次+用户点"以后自动"→ 升 L3；随时一键降回；出一次错该类自动降回 L2 并进 AI 复盘。

**硬线**：①花钱（付款/转账/下单）永远≤L2，儿童角色连 L2 无（只能发起申请给管理员批）②对外发声（发邮件/公告/回客户）最高 L2，必经人眼 ③L3 类动作设月度次数/金额上限，超限自动降 L2。

**落地**：manifest 的 act 动作逐个标档位，装面板时用户可见"会自动做：①②③（可关）；做前会问你：④⑤"；面板设置页"AI 授权"区逐动作调档/设额度/看干活日志；对话式调档走受控进化提案。

## 第 5 章 分类全景与上架顺序

### 5.1 四层 18 类全景

| 层 | 类 |
|----|-----|
| 决策层 | ①经营参谋（含传播情报）②年度规划 ③作战室(=目标引擎页面) ④决策日志 |
| 经营层 | ⑤客户·销售（含客户情报画像）⑥财务 ⑦库存·进销存 ⑧电商·门店 ⑨采购·比价 ⑩营销·广宣 ⑪客服·售后（含 AI 客服） |
| 职能层 | ⑫人事·考勤（含口述日报）⑬行政·合规 ⑭法务·合同 ⑮质量·安全 ⑯IT·订阅资产 |
| 协作层 | ⑰工作汇报 ⑱公告·制度 |

**营销·广宣是枢纽类**：预算连财务（审批中心）、线索连销售、排期连目标引擎、效果数据回流月度简报——涉及目标与资金的交叉功能。

垂直行业模板（生产排程/餐饮/教培等）为独立捆绑包，不在基础 14 类内。

### 5.2 开发与上架顺序（完整单件原则）

| 批次 | 内容 | 完成标准 |
|------|------|---------|
| **B1** | 调度内核 + 通用机制（4.1~4.5）+ **客户·销售面板** | 第一个面板端到端跑通四层智能 |
| **B2** | 财务 + 库存 + 工作汇报 | 四大命脉面板全闭环 |
| **B3** | 横切三件套 + 作战室页面 | 审批/通知/审计可用，老板一屏总览 |
| **B4** | 目标引擎 V1（手动目标+每日例检）+ **营销·广宣面板** | 目标闭环跑通；广宣"预算→投放→线索→ROI"链路可用 |
| **B5+** | 其余全部类目按"完整单件"逐个上架（客服·售后/法务/电商优先） | 每件全闭环 |

|----------|------------------|---------|

## 第 8 章 目标引擎（旗舰插件，panel_id: `goal-engine`）

### 8.1 闭环

```
老板定目标 → AI 分解到部门任务 → 每日例检(实际 vs 计划)
→ 偏差分析+调整建议 → 老板批准 → 下发任务到对应面板
→ 完成度自动流入绩效考核（奖惩联动）
```

### 8.2 数据表

**panel_goal_goals**：goal_id / title / period(季·年) / target_metrics_json(如 `{revenue:1000000}`) / status(进行中·达成·未达成·调整) / review_at

**panel_goal_tasks**：task_id / goal_id / dept / assignee / plan_desc / plan_value / actual_value / deadline / status

**panel_goal_checkins（例检记录）**：checkin_id / goal_id / date / actual_snapshot_json / deviation_text / ai_suggestions_json / boss_decision(采纳·调整·忽略)

### 8.3 每日例检（analyze 任务）

输入：本目标全部关联面板当日实际数据 → 输出：偏差说明 + 1~3 条调整建议（按风险排序）→ 作战室"今日结论"卡。**建议不自动执行**：老板点"采纳"后才生成任务下发；点"调整"进入目标修订（修订留痕进决策日志）。

### 8.4 分期

| 期 | 范围 |
|----|------|
| V1（B4 批次） | 手动定目标 + 每日例检简报 + 手动分解任务 |
| V2 | AI 自动分解目标到部门 + 一键下发 + 完成度自动联动绩效奖惩 + 依赖冲突检测（如"销售目标需要库存备货，但采购资金超预算"跨面板预警） |

## 第 11 章 合规红线（写进每一份对外协议）

1. 员工数据：知情同意前置；分析只输出客观行为数据，禁止"态度/忠诚"定性
2. 隐私档位联动：严格档下敏感字段（金额明细/客户信息）不出本机
3. 推广功能禁止刷量/水军/虚假流量（反不正当竞争法）
4. 数据可导出、可彻底删除（用户数据主权）
5. AI 建议免责声明：决策人为老板，平台不承诺经营结果
6. **AI 替代边界**：AI 只替代初稿/整理/提醒/信息四类劳动；签字、盖章、付款、终审必须是人

### 11.1 公司侧询问提示场景
