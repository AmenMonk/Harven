一、产品定位

1.1 一句话定位

Harven AI 是一款纯本地运行的私有 AI 助手，永久免费，不做付费会员。

1.2 核心理念

维度 说明
隐私优先 100% 本地运行，数据不出设备，无遥测、无隐私泄露
永久免费 不设付费墙，所有功能免费开放
开源可控 Apache-2.0 协议，源码完全透明
设备绑定安全 硬件指纹+设备绑定，防止未授权克隆
独立性 不与其他实例通信，不外传设备指纹

1.3 核心功用

  • AI 对话：三种模式自由切换 —— 云端大模型（DeepSeek/Kimi 等 24 厂商，即开即用） / 魔搭 GGUF 直连（默认，零依赖）/ Ollama（可选本地引擎）
  • 知识库管理：本地文件（PDF/TXT/DOCX）导入后 FAISS 向量检索，打造个人知识助手
  • 联网搜索增强：内置 Bing（免费网页解析）+ SearXNG（自托管），可按需开关
  • 多模型外脑：支持 24 个国内外模型厂商，可自由扩展
  • 技能系统：可安装社区技能包，扩展 AI 能力
  • IoT 设备联动：MQTT/HTTP/WebSocket 协议接入智能设备
  • 手机联动：Token + 二维码 + 代理对话，手机端远程访问
  • 受控进化：AI 生成改进提案 → 用户审批 → 自动应用，渐进式自我优化

三、核心功能详解

3.1 三种查询模式

Harven AI 前端提供三个按钮，对应用户可选的三种工作模式。三种模式共享知识库检索、Skills 注入、用户画像、习惯上下文、诚实约束——区别在于最终回答由谁生成：

按钮 模式 回答引擎 共享能力 适用场景
🏠 本地 kb_only 本地引擎（魔搭GGUF/Ollama） 知识库 + Skills + 画像 + 习惯 + 诚实 离线/隐私，数据不外传
🤖 外脑 direct 外部模型（DeepSeek/豆包等） 知识库 + Skills + 画像 + 习惯 + 诚实 需要更强推理能力
🤝 协作 collab 外脑分析 → 本地整合输出 知识库 + Skills + 画像 + 习惯 + 诚实 综合实力最强

协作模式详解（两种配方，集成在 🤝按钮和左侧下拉菜单）：

配方 流程 适用
🧪 配方1 规划 → 执行 → 润色 复杂任务，分步推进
🧠 配方2 思考 → 参考 → 整合 深度分析，多视角对比
特性 说明
控制 🤝按钮切换开关 + 下拉选择配方 + config.yaml collab.enabled 字段
外脑选择 需用户在设置→模型管理中手动指定协作外脑（代码级默认 doubao，实际取决于 config.yaml collab_foreign_model）
隐私保护 三档：严格（只传必要上下文）/ 平衡 / 全量（默认）
安全规则 禁止两个外部模型同时工作；协作模式下跳过自动路由

代码逻辑（engine.py）：

用户消息 → Agent 意图路由 → KB检索 → 联网搜索(可选) →
[🤝 若协作开启: 外脑分析 → 结果注入本地 prompt]
if kb_only:  纯本地引擎，不外传
if direct:   外部大模型直接回答
→ SSE 流式输出

注意：引擎内部保留 auto 作为未选择时的默认值，但前端不暴露。用户实际可见的三个选项就是 🏠本地 / 🤖外脑 / 🤝协作。

3.1.1 🏠 双模配置面板（🆕 v2026-06-27）

本地双模模式下，用户可在 设置 → 模型管理 → 🏠 双模配置 中精细配置大脑模型和工具模型：

配置项 功能 默认值
🧠 大脑模型 选择负责对话/推理的通用模型（下拉选择） 自动使用当前模型
🎨 工具模型 勾选垂直模型自动被哈文调度执行专项任务（多选） 无

API 端点：

方法 端点 说明
GET /api/collab/dual-config 读取已存配置（{brain, tools}）
POST /api/collab/dual-config 保存配置到 config.yaml（{brain, tools}）

配置文件（config.yaml）：

local_dual_brain: ""              # 大脑模型名，空=自动使用当前模型
local_dual_tools: []             # 工具模型名列表

模型分类逻辑：通用模型 = 所有 Ollama 已安装模型 − 垂直专用模型（musicgen / bark / stable-diffusion / 多模态 / embedding 等），确保大脑不会选到无法对话的专用模型。

3.2 多模型系统（24 个厂商 + 双路径本地）

通过 MultiModelManager 统一管理，支持本地双路径（魔搭直连 / Ollama）和 24 个云端厂商：

国际厂商（11个）： OpenAI、Claude(Anthropic)、Gemini(Google)、Groq、Perplexity、Mistral、Together、OpenRouter、HuggingFace、Cohere、xAI(Grok)

国内厂商（13个）： DeepSeek、通义千问、Kimi(Moonshot)、豆包(火山引擎)、元宝、百川、智谱、零一万物、阶跃星辰、MiniMax、文心一言、星火、天工、硅基流动

特点： - 出厂不内置任何 API 密钥，用户自行配置 - 统一 OpenAI-compatible API 接口（_generate_openai_compatible()） - Gemini/Claude 特殊鉴权（_build_auth_headers() 处理讯飞等非标准鉴权） - 免费优先（标注 "free": True 的厂商排前面）

3.3 联网搜索系统

技术实现： - Bing 网页解析（免费，无需 API Key，web_search.py 直接解析搜索结果页） - SearXNG 自托管元搜索（需本地 Docker，隐私最强） - 用户可在设置中自由切换 关闭/Bing/SearXNG 三种模式 - 搜索结果注入上下文，本地引擎整合分析

特色： - 搜索失败时注入 ⚠️ 标记到上下文，模型诚实告知 - 对话中传 web_search: true 即可触发，无需全局开关

3.4 知识库系统

核心组件：

组件 功能
knowledge_base.py FAISS 向量库（HNSW 索引），支持 PDF/TXT/DOCX/MD 导入
content_reader.py 网页内容提取（Bilibili/抖音等链接解析）
memory.py 短期（对话缓存）+ 长期（向量持久化）双轨记忆
memory_dreaming.py 闲置时离散记忆片段随机组合，模拟"梦游"发现关联
memory_eviction.py 基于使用频率/时间的记忆淘汰策略
active_memory.py 活跃记忆高速缓存，加速上下文召回

技术细节： - FAISS 索引存储在 data/faiss/ - 内容分块存储，支持语义相似度检索 - SQLite 存储元数据（文件路径、导入时间、大小等）

3.5 安全系统

多层安全架构（非序列化流程，各层独立工作）：

安全层 作用
Prompt Injection 防御 30 条关键词检测，"忽略指令"、"绕过限制"等攻击
道德约束 「诚实」原则，analyze_intent 始终返回 safe，不审核不锁死
设备指纹 收集 MAC/CPU/主板信息，绑定设备防克隆
出站白名单 37 个域名白名单，外部连接仅限已注册的 AI 厂商
代码沙箱 隔离执行环境，限制系统调用
速率限制 API 级别限制，防止资源耗尽
文件扫描 5 层扫描（扩展名/大小/Magic字节/内容模式/ClamAV）
三库隔离 对话库/知识库/配置库物理分离

3.6 Agent 调度引擎

Harven AI = Agent 管理与调度平台。Agent 是 Harven 的一等公民，其他模块为其服务。

核心文件： | 文件 | 职责 | |------|------| | agent_registry.py | Agent 注册中心：注册/发现/路由，13 个内置 Agent | | agent_routes.py | API 接口：GET/POST/PUT/DELETE Agent | | agent_runner.py | Agent 执行引擎（函数模块，run_script_agent） | | multi_agent.py | 多 Agent 协作调度 |

内置 Agent 清单（13 个）： | Agent | 触发意图 | 特长 | |-------|---------|------| | code_reviewer | 审查/检查代码/debug | 代码审查 + 安全分析 | | coder | 写代码/生成代码 | 代码生成 | | translator | 翻译 | 多语言翻译 | | teacher | 解释/教学 | 教学讲解 | | file_explorer | 列出文件/检索 | 文件系统浏览 | | researcher | 研究/调研 | 深度分析 | | data_analyst | 分析数据/表格 | 数据洞察 | | planner | 计划/规划 | 任务拆解 | | critic | 批判/找漏洞 | 批判性思维 | | ops_agent | 安装/运维/日志 | 系统运维 | | computer_use | 控制电脑/截图 | 桌面操作 | | music_generator | 电子音乐/EDM | 音乐生成 | | ace_step | 作曲/生成音乐 | 音乐创作（ACE-Step） |

Agent 路由机制：

用户消息 → 正则意图匹配(INTENT_ROUTES) → 路由到对应 Agent
         → Agent 独立 system_prompt + 专属 Skills → 生成回复

自生成 Agent：通过设置面板「🏭 Agent 工坊」填写名称+角色描述→AI 自动生成 system_prompt→一键注册，或直接调用 POST /api/agents/register。自定义 Agent 自动加入路由表。删除只影响自定义 Agent，内置 13 个不受影响。

3.11 受控进化系统

设计理念：AI 可以在对话中提出改进建议，但必须经用户审核批准后才生效。

工作流程：

1. 用户或 AI 提交 proposal（通过设置面板或对话触发）
2. proposal 进入 pending_proposals 队列
3. 前端显示"待审批"角标 + 提案详情
4. 用户 approve → 白名单校验 → 仅 config_change 类型自动应用
5. 其他类型（skill/knowledge/other）标记为需手动处理

安全机制： - 白名单控制：仅允许修改 skills/ 和 config.yaml 指定键 - 修改前 diff 预览 - 修改后自动验证（前后端一致性检查） - 异常时自动回滚

3.12 手机联动

连接方式： 1. 桌面端生成 Token + 二维码 2. 手机端扫描二维码 → 获得临时 Token 3. 手机通过代理 API 发送消息 → 桌面端 AI 处理 → 返回结果

安全：Token 时效性 + 设备验证，不暴露桌面端敏感信息。

4.3 行业垂直 AI 模式

Harven AI 的目标不是做一个通用聊天工具，而是让每个行业都有专属的本地 AI。

核心逻辑

本地模型（大脑）
  + 行业知识库（专业领域知识，大模型不具备）
  + 连接层（Agent / Skill / 中间代码）
  + 外部系统（IoT 设备 / 客户管理软件 / 邮件 / 电话）
  = 行业 AI 解决方案

通用大模型不懂你的行业术语、不了解你的设备协议、不知道你的客户数据。Harven 把这一切补上：

层 作用 举例
🧠 本地模型 推理、理解、生成 分析设备日志、阅读合同条款
📚 行业知识库 专业术语、操作手册、历史案例 化工厂安全手册、律所判例库
🔌 连接层 对接外部系统、执行动作 自动发邮件、调 CRM 接口、打电话
⚙️ IoT / 设备 采集数据、接收指令 产线传感器、数控机床、环境监控

5.3 SQLite + FAISS 配置优化（🆕 v2026-06-24）

# SQLite 性能
PRAGMA journal_mode=WAL        # 写操作快 2-5×
PRAGMA synchronous=NORMAL      # 减少磁盘 fsync
PRAGMA busy_timeout=5000       # 5秒锁等待，避免阻塞
PRAGMA foreign_keys=ON         # 强制外键约束

# FAISS 磁盘映射（SSD/HDD 自适应）
faiss.read_index(path, faiss.IO_FLAG_MMAP)  # 不占满内存，启动快 5×

自动适配：启动时检测硬件，所有用户均使用 FAISS mmap 策略以避免内存占满。

# 解决多线程并发锁死（2026-06-12 修复）
conn = sqlite3.connect(db_path, check_same_thread=False, timeout=15)
conn.execute("PRAGMA journal_mode=WAL")          # 写前日志，读写并发
conn.execute("PRAGMA foreign_keys=ON")            # 外键约束
conn.execute("PRAGMA busy_timeout=5000")          # 忙等待 5 秒
conn.execute("PRAGMA synchronous=NORMAL")         # WAL 正常同步

7.1 环境要求

Harven AI 支持两种运行方式，CPU-only 即可起步。

☁️ 云模型模式（推荐入门 — 无需任何硬件门槛）

组件 要求
CPU 任意（能开浏览器就行）
内存 4 GB
显卡 不需要
磁盘 500 MB（安装包 + .venv）
Python 3.10+
Ollama ❌ 不需要

最低门槛（CPU-only 本地模式）

组件 要求
CPU 4 核（任意架构）
内存 8 GB
显卡 不需要（纯 CPU 推理）
磁盘 10 GB 可用
Python 3.10+
Ollama 可选（魔搭直连无需 Ollama）

纯 CPU 可运行 qwen2.5:3b / 7b 量化版，速度约 3-5 tokens/s，适合轻度使用。

GPU 加速模式（模型越大要求越高）

模型规模 显存 内存 参考显卡
3B–7B 0–6 GB 8–12 GB GTX 1660 / 无独显
8B–14B 6–10 GB 12–16 GB RTX 3060+
32B 12–24 GB 32 GB+ RTX 4080+
70B 24–48 GB 48 GB+ RTX A6000 / 多卡

推荐机制：启动时 detect_hardware() 自动获取当前设备的 CPU、内存、显存， 与内置模型数据库（38 个模型，每个标注 min_ram_gb / min_vram_gb）逐一比对， 分成三档——✅ 推荐（硬件满足）/ ⚠️ 勉强（接近边界）/ ❌ 不支持（硬件不足）， 最终在前端展示当前设备能流畅运行的模型清单。

以上表格为通用参考，实际推荐以 Harven AI 硬件检测结果为准。
